LLM_local — how it was built

A from-scratch GPT-style language model. Every component — tokenizer, architecture, training loop, and the in-browser inference engine — is implemented by hand, with no tiktoken, transformers, or nn.Transformer shortcuts. This page walks through each step.

Overview & architecture

LLM_local is a decoder-only GPT trained on public-domain literature (Pride & Prejudice, War of the Worlds, Great Expectations, Moby-Dick, Frankenstein, Alice in Wonderland). It follows the standard modern LLM recipe, built bottom-up:

StageFileWhat it does
Tokenizationbpe.pyByte-level BPE tokenizer, trained from scratch
Modelmodel.pyGPT Transformer (causal self-attention)
Pre-trainingtrain.pyNext-token cross-entropy, AdamW + LR schedule
Inferencegenerate.pySampling / chat from a checkpoint
Fine-tuningfinetune.pySupervised fine-tuning (SFT) on instructions
Web exportexport_for_web.pyWeights → model.bin / model.json
Model size (main run): 4 layers · 4 heads · 192-dim · 128-token context · 6000-token vocab ≈ 2.9M parameters. Chosen to be trainable on CPU in a single session while still being a genuine Transformer.

Step 1 — Data & tokenization (byte-level BPE)

Raw text is split into words, each word is mapped to its bytes and rendered as unambiguous Unicode glyphs (the GPT-2 scheme), then merged by frequency to build a vocabulary. This is implemented from scratch in bpe.py — no tiktoken or tokenizers library.

1Pre-tokenize with the GPT-2 regex so punctuation and whitespace become their own tokens.
2Byte-map each word's UTF-8 bytes to the 256 printable glyph chars so the merge space is stable.
3Learn merges by counting adjacent symbol pairs across the corpus and repeatedly merging the most frequent pair until the target vocab size is reached.
# train a 6000-token byte-level BPE on the corpus
from bpe import BPETokenizer
tok = BPETokenizer.train("data/*.txt", vocab_size=6000, out_path="out/tokenizer.json")

ids  = tok.encode("It is a truth universally acknowledged")
text = tok.decode(ids)          # exact round-trip guaranteed

Round-trip is exact: tok.decode(tok.encode(x)) == x. The same algorithm is ported to JavaScript (site/llm-tokenizer.js) so the browser produces identical token ids.

Step 2 — Model architecture (Transformer)

A decoder-only Transformer. Each block is pre-LayerNorm (LayerNorm → sublayer → residual), using causal multi-head self-attention and a GELU MLP. The output head re-uses the token embedding (weight tying). Implemented in model.py.

class GPT(nn.Module):
    def __init__(self, config):
        self.tok_emb = nn.Embedding(vocab, n_embd)
        self.pos_emb = nn.Parameter(torch.zeros(1, block_size, n_embd))
        self.blocks  = nn.ModuleList([Block(config) for _ in range(n_layer)])
        self.ln_f    = nn.LayerNorm(n_embd)
        self.head    = nn.Linear(n_embd, vocab, bias=False)
        self.head.weight = self.tok_emb.weight   # weight tying

Causal attention masks future positions so the model only conditions on the past:

def _attn(self, x):                      # x: [B, T, C]
    B, T, C = x.size()
    q, k, v = self.c_attn(x).split(C, dim=2)
    q = q.view(B, T, H, D).transpose(1, 2)   # [B, H, T, D]
    att = (q @ k.transpose(-2, -1)) / math.sqrt(D)
    att = att.masked_fill(torch.tril(torch.ones(T, T)) == 0, float('-inf'))
    att = F.softmax(att, dim=-1)
    return self.c_proj((att @ v).transpose(1, 2).reshape(B, T, C))

Step 3 — Pre-training

The expensive phase: predict the next token across the corpus and backpropagate. train.py uses AdamW with linear warmup + cosine decay, gradient clipping, and a vectorized random-window Dataset so the data loader never materializes 1.8M tokens at once.

optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=0.1)
scheduler = cosine_with_warmup(optimizer, warmup=200, max_steps=steps)
for x, y in loader:                    # x: tokens, y: x shifted by one
    logits, loss = model(x, y)
    loss.backward(); clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step(); scheduler.step()

Loss at step 0 is ≈ ln(6000) ≈ 8.7 (random init); it falls steadily as the model learns word statistics. Checkpoints save to out/best.pt and out/ckpt_*.pt.

Step 4 — Fine-tuning & alignment (SFT)

After pre-training the model is a "next-word predictor", not an assistant. Supervised fine-tuning continues training on instruction/response pairs (data/sft.jsonl) to shape it into a chat assistant. finetune.py resumes from a checkpoint:

python finetune.py --data data/sft.jsonl --base out/best.pt --steps 300

The same template is used in chat mode in the browser playground (User: …\nAssistant: …).

Running it in the browser

Netlify can't run Python, so the trained weights are exported and the model is re-implemented in pure JavaScript — no server, no API, fully client-side:

ArtifactPurpose
export_for_web.pyWrites model.bin (float32 weights) + model.json (config) + tokenizer.json
site/llm-tokenizer.jsJS port of the byte-level BPE
site/llm-core.jsJS port of the GPT forward pass
site/index.html + app.jsDark-themed playground (generate + chat)
Verification: the JS forward pass was cross-checked against PyTorch token-by-token. Predicted argmax and full logits match exactly (max difference ≈ 1.3, i.e. float rounding only), so the browser produces the same text as the trained Python model.

How to run / reproduce

# 1. environment (torch has no wheels for Python 3.14 — use 3.12)
uv venv --python 3.12 .venv && .venv/Scripts/python.exe -m pip install torch==2.9.0+cpu numpy regex

# 2. build tokenizer + train
.venv/Scripts/python.exe train.py --vocab_size 6000 --n_layer 4 \
    --n_head 4 --n_embd 192 --block_size 128 --batch_size 64 --steps 3000

# 3. generate / chat
.venv/Scripts/python.exe generate.py --prompt "It is a truth universally acknowledged"

# 4. export for the web playground
.venv/Scripts/python.exe export_for_web.py out/best.pt site

On this machine the shell leaks PYTHONPATH into the wrong venv, so every Python call is prefixed with unset PYTHONPATH.
